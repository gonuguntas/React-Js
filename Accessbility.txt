Golden Rule - Use semantic HTML first - Semantic HTML gives accessibility for free.

1. Text Accessibility 
 bad - font-size: 10px;
 better - font-size: 16px;
Only One H1 Per Main Page
Avoid ALL CAPS Text - All caps reduces readability.
Use Clear and Simple Language - Keep content easy to understand for Cognitive disability persons.
Allow Text Zoom - Users should be able to zoom to: 200%
Adequate Line Spacing, Adequate Paragraph Spacing
Use Lists for Related Content


2. Images Accessibility
Informative image → meaningful alt text.
Decorative image → empty alt.

3. Links Accessibility (<a>)
meaning less - Click here
clear meaning - View Products

4. Button Accessibility 
use button  tag only. Don't use like <div>save</div> and adding css
Buttons automatically support:
✅ Keyboard
✅ Focus
✅ Screen readers
5. Form Accessibility
Label Every Input, Required Fields, Error Handling-Screen readers announce the error.
7. Focus Visibility
Never remove focus outline.
button:focus {
outline: 2px solid blue;
}
Keyboard users must know where focus is.

8. Color Accessibility
Don't Use Color Alone - Color blind users may not notice
Use:  Text, Icons, Labels along with color.

Good Contrast - According to WCAG, normal text should have at least a 4.5:1 contrast ratio and large text should have at least a 3:1 ratio
Hard to read.
color: lightgray;
background: white;
High contrast is better.
color: black;
background: white;

10. Dynamic Content Accessibility
When content changes dynamically:
Used for:
Success messages
Notifications
API responses

11. Tables Accessibility  -  add scope for <th>

12. Accessibility for Modals
When modal opens:
✅ Focus moves inside modal
✅ ESC closes modal
✅ Focus returns to previous element

For hearing-impaired users   ----  I ensure that any audio information is also available visually through captions, transcripts, visible notifications, error messages, and alerts. I never rely on sound alone to communicate important information. This makes the application accessible to deaf and hard-of-hearing users.

To support users with cognitive disabilities, I use simple language, clear instructions, meaningful error messages, consistent navigation, step-by-step workflows, progress indicators, and avoid requiring users to remember information. The goal is to reduce mental effort and make tasks easy to understand and complete. Without confusing means different pages of website having different colors or designs or font styles.

For users with motor disabilities, I ensure the application is fully keyboard accessible, provide visible focus indicators, use large clickable targets, maintain spacing between controls, avoid drag-only or gesture-only interactions, allow sufficient time for actions, and prefer native HTML elements because they provide built-in accessibility support.
