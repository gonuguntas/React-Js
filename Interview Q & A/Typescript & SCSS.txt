Variables
------
Variables are a way to store information that you can re-use later.
$myFont: Helvetica, sans-serif;
$myColor: red;
$myFontSize: 18px;
$myWidth: 680px;

body {
  font-family: $myFont;
  font-size: $myFontSize;
  color: $myColor;
}

Sass Variable Scope
Sass variables are only available at the level of nesting where they are defined.
$myColor: red;

h1 {
  $myColor: green;
  color: $myColor;
}

p {
  color: $myColor;
}

Using Sass !global
-----------------
!global indicates that a variable is global, which means that it is accessible on all levels.
$myColor: red;

h1 {
  $myColor: green !global;
  color: $myColor;
}

p {
  color: $myColor;
}

Sass Nested Rules
-----------------
Sass lets you nest CSS selectors in the same way as HTML.

Sass Importing Files
---------------------
Just like CSS, Sass also supports the @import directive.

The @import directive allows you to include the content of one file in another.
@import "variables";
@import "colors";

Sass Mixins
---------------
The @mixin directive lets you create CSS code that is to be reused throughout the website.

The @include directive is created to let you use (include) the mixin.
@mixin important-text {
  color: red;
  font-size: 25px;
}
sing a Mixin
The @include directive is used to include a mixin.

.danger {
  @include important-text;
  background-color: green;
}
Sass @extend Directive
---------------------------
The @extend directive lets you share a set of CSS properties from one selector to another
.button-basic  {
  border: none;
  padding: 15px 30px;
  text-align: center;
  font-size: 16px;
  cursor: pointer;
}

.button-report  {
  @extend .button-basic;
  background-color: red;

1. What is TypeScript and why do we use it?

TypeScript is a superset of JavaScript that adds:

Static typing
Compile-time error checking
Better IDE support
Improved maintainability

What is Type Inference?
	Type Inference is the feature where TypeScript automatically detects and assigns a type to a variable, function return value, parameter, array, object, etc., without explicitly writing the type.
1. Reduces Boilerplate Code - Less code
2. Provides Type Safety 
3. Improves Developer Productivity - Less typing, faster development.

Basic Data Types in TypeScript
string,number,boolean,null,undefined,array,object,tuple,enum,any,unknown,void,never,bigint,symbol

interface vs type
	Interface is mainly used to define and extend object structures with declaration merging support, whereas Type Alias is more flexible and can represent primitives, unions, tuples, functions, and objects.

Which is better, Interface or Type?
	Neither is universally better. Use interface for object structures and extensible contracts, and use type alias when working with unions, tuples, primitives, or complex type compositions.

Interface : Used to define the shape of an object.
1) Supports inheritance using extends.
2) Interface Supports Declaration Merging : When you declare an interface with the same name multiple times in same scope, TypeScript merges all of their members into one unified type

interface Person {
  name: string;
}

interface Employee extends Person {
  id: number;
}

const emp: Employee = {
  name: "Nagesh",
  id: 101
};

------auto merging----------
interface User {
  name: string;
}

interface User {
  age: number;
}

const user: User = {
  name: "Nagesh",
  age: 30
};


type : Type aliases can represent primitive types, interfaces cannot.
1) Type Alias Uses Intersection (&) - Type aliases combine multiple types using intersection (&).
2) Type Alias Supports Union Types
3) Type Alias Supports Tuples
4) Type Alias Supports Function Types

---- intersection-----
type Person = {
  name: string;
};

type Employee = Person & {
  id: number;
};

const emp: Employee = {
  name: "Nagesh",
  id: 101
};

---- premitives-----
type ID = string;
let userId: ID = "EMP101";

---- union----
type Status = "success" | "error" | "loading";
let state: Status = "success";

-----touples----
type Employee = [number, string];
const emp: Employee = [101, "Nagesh"];

------ functions------
type Add = (a: number, b: number) => number;
const sum: Add = (a, b) => a + b;


Union Types in TypeScript
Union types allow a variable to accept more than one type while maintaining type safety.
type Id = string | number;
let value: string | number;

type Status = "loading" | "success" | "error";

let apiStatus: Status;
apiStatus = "loading"; // ✅
apiStatus = "success"; // ✅
apiStatus = "error";   // ✅
apiStatus = "pending"; // ❌

Literal Unions : combine specific, exact values (strings, numbers, or booleans) using the pipe (|) operator to create a strict, custom type.

type Theme = "light" | "dark" | "system";
type DiceRoll = 1 | 2 | 3 | 4 | 5 | 6;
type Toggle = true | false;


type Status = "loading" | "success" | "error";

interface ApiResponse {
  id: number;
  status: Status; // The interface uses your custom union type here
}

union with objects

type Admin= {name: string}
type User= {age: number}
type Person = Admin | User
const p1:Person = { name: "nag"}
const p2:Person = { age: 35 }    //  both are valid

---Problem with Union---
function printId(id: string | number) {
  console.log(id.toUpperCase());
}
Error : number doesn't have toUpperCase()
TypeScript does not know whether id is a string or number at runtime.

---Solution: Type Narrowing---
function printId(id: string | number) {
  if (typeof id === "string") {
    console.log(id.toUpperCase());
  } else {
    console.log(id.toFixed(2));
  }
}

When using unions, TypeScript requires type narrowing before accessing type-specific properties.


----any data type in typescript---
any turns off or disables TypeScript type safety and behaves like plain JavaScript.
1) Accepts Any Value
2) Allows Any Operation
let value: any = "Hello";
value.toUpperCase();
value.toFixed(2);
value.randomMethod();

---When Does TypeScript Infer any?---
1) Variable Declared Without Value
let data;
data = "Hello";
data = 100;
2) Function Parameters Without Types
	function greet(name) {
	  return name;
	}
3) JSON/API Data - Historically, parsed JSON often behaves like any.
	const response = JSON.parse(data);
	response.xyz(); // No compile-time error
4) Third-Party Libraries Without Type Definitions
	import xyz from "old-library";
	xyz // inferred as any

Explicit any is intentionally declared; implicit any occurs when TypeScript cannot infer a specific type.

---When Should We Use any?---
Use only when the type is truly unknown.

Examples:

✅ Migrating JavaScript to TypeScript

✅ Temporary prototype code

✅ Third-party libraries lacking typings

✅ Dynamic data where type cannot be determined immediately

---Why is any not recommended?---
Removes type safety.
Hides bugs.
Reduces code quality.
Weakens IntelliSense.
Defeats the purpose of TypeScript.


--- unknown in typescript---
any disables type checking completely, whereas unknown preserves type safety by requiring type checks before using the value.
1) Can Store Any Value
2) Cannot Use Directly
3) Type Narrowing - Before using an unknown value, we must narrow its type.
	let value: unknown = "Hello";

	if (typeof value === "string") {
	  console.log(value.toUpperCase());
	}


---Using Type Assertions---
let value: unknown = "Hello";
console.log((value as string).toUpperCase());

---Why use unknown instead of any?---
Provides type safety.
Prevents invalid operations.
Forces type narrowing.
Reduces runtime errors.
Recommended for external or dynamic data.


--- never data type in typescript ---

never means a function never finishes executing at all (it crashes or runs forever).
void means a function completes successfully but returns nothing useful (implicitly returns undefined).

// Example A: Throws a runtime error (never completes)
function apiCrash(message: string): never {
  throw new Error(`Critical API Failure: ${message}`);
}

// Example B: Infinite process loops (never ends)
function startEventLoop(): never {
  while (true) {
    // Listens for server events indefinitely
  }
}



---Type Assertions in TypeScript ---
Type Assertion is a TypeScript feature that allows developers to override TypeScript's inferred type and explicitly tell the compiler what type a value should be treated as.

Type Assertion vs Type Annotation
Type Annotation - You declare the type while creating the variable.
let name: string = "Nagesh";

Type Assertion - You tell TypeScript what type to treat the value as.
const value = "nag" as string
const input = document.getElementById("username") as HTMLInputElement;
console.log(input.value);

Type Assertion vs Type Casting : Many developers say Type Casting, but TypeScript actually uses Type Assertions.
Type casting means converting data type but  type assertion means telling to typescript exact data type.


Double Assertion :  Double assertions should be avoided unless absolutely necessary because they bypass TypeScript's safety checks.

const value = "Hello";
const num = value as unknown as number;

--- When Should We Use Type Assertions? ---
DOM manipulation
API responses
Working with unknown
Third-party libraries
Event targets

Does Type Assertion change the value at runtime?
Answer:  No.
It only affects compile-time type checking and does not perform any runtime conversion.

--- Type Assertion (as) vs typeof ---
Type Assertion - ✅ Used when you already know the type and want to tell TypeScript.

typeof - ✅ Used when TypeScript needs to check the actual type at runtime.


--- union ( |)  vs intersection ( & ) ---
	Union (|) allows a value to be one of several types (OR), whereas Intersection (&) combines multiple types into a single type that must satisfy all of them (AND).


--- utility types ---
Partial: changes all the properties in an object to be optional.
interface Point {
  x: number;
  y: number;
}

let pointPart: Partial<Point> = {}; // `Partial` allows x and y to be optional
pointPart.x = 10;

Required: changes all the properties in an object to be required.
interface Car {
  make: string;
  model: string;
  mileage?: number;
}

let myCar: Required<Car> = {
  make: 'Ford',
  model: 'Focus',
  mileage: 12000 // `Required` forces mileage to be defined
};

Record:  is a shortcut to defining an object type with a specific key type and value type.
const nameAgeMap: Record<string, number> = {
  'Alice': 21,
  'Bob': 25
};

Omit: removes keys from an object type.
interface Person {
  name: string;
  age: number;
  location?: string;
}

const bob: Omit<Person, 'age' | 'location'> = {
  name: 'Bob'
  // `Omit` has removed age and location from the type and they can't be defined here
};

Pick: removes all but the specified keys from an object type.
interface Person {
  name: string;
  age: number;
  location?: string;
}

const bob: Pick<Person, 'name'> = {
  name: 'Bob'
  // `Pick` has only kept name, so age and location were removed from the type and they can't be defined here
};
Readonly: is used to create a new type where all properties are readonly, meaning they cannot be modified once assigned a value.
interface Person {
  name: string;
  age: number;
}
const person: Readonly<Person> = {
  name: "Dylan",
  age: 35,
};
person.name = 'Israel'; // prog.ts(11,8): error TS2540: Cannot assign to 'name' because it is a read-only property.


What is Enum?
Enum (Enumeration) is a TypeScript feature used to define a set of named constants.
Makes code more readable, maintainable, and type-safe.
Useful when a variable can have only a fixed set of values.
enum Direction {
Up,   //0
Down,  //1
Left,  //2
Right  // 3
}

console.log("Hello, World!", Direction.Up)   -- 0
By default, enums start from 0.
Numeric enums automatically increment values. if first value is 10 next is 11,12....
✅ Instead of using magic numbers (0, 1, 2), use meaningful names.
enum ApiStatus {
Loading = "LOADING",
Success = "SUCCESS",
Error = "ERROR"
}

Generic Constraint

What is a generic constraint?
	A generic constraint restricts the types that can be passed to a generic using the extends keyword.

Why use constraints?
	To ensure a generic type contains required properties or methods.

function getLength<T extends { length: number }>(value: T) {
  return value.length;
}

getLength("Hello");
getLength([1, 2, 3]);


Example 1: Object Constraint

function printId<T extends { id: number }>(user: T) {
  console.log(user.id);
}

printId({
  id: 1,
  name: "John"
});


Example 2: Key Constraint (keyof)

function getProperty<T, K extends keyof T>(
  obj: T,
  key: K
) {
  return obj[key];
}

const user = {
  id: 1,
  name: "John"
};

getProperty(user, "name");


Example 3: Reusable Interface Constraint

interface HasName {
  name: string;
}

function greet<T extends HasName>(obj: T) {
  console.log(`Hello ${obj.name}`);
}

greet({
  name: "Nageswara",
  age: 30
});


Example 4: API Response

interface BaseResponse {
  success: boolean;
}

function handleResponse<T extends BaseResponse>(
  response: T
) {
  console.log(response.success);
}

handleResponse({
  success: true,
  data: []
});
